# 测试说明

> 覆盖范围：主链路、数据缺失/接口异常、极端与合规边界。全部 22 个用例通过：
> `python -m pytest tests/ -v`（22 passed）

## 一、主链路（tests/test_main_chain.py + test_consolidation.py）

| 用例 | 覆盖点 | 断言要点 |
|---|---|---|
| `test_rumor_to_denial_flips_conclusion_and_notifies` | 传闻 → 官方否认的结论翻转 | 事件状态 emerging→denied；传闻与澄清归并为同一命题；生成 state_change 通知与版本留痕 |
| `test_conflicting_evidence_marks_disputed` | 证据冲突 | 否认后又证实 → 命题与事件进入 disputed，生成 conflict 通知 |
| `test_same_event_merges_by_entity_and_topic` | 同一事件识别（主体+话题） | 同事件两篇公告合并为一个事件，事实主张计数正确 |
| `test_correction_flips_existing_proposition_via_fuzzy_match` | 更正路径 + 命题模糊归并 | 更正公告命题与原文略有出入（相似度≥0.75）仍命中既有命题，判定 confirmed→corrected |
| `test_closure_supersedes_and_versions_accumulate` | 完结优先级流转 | 立案证实 → 终止上市：状态 closed，每个版本带 before/after 快照 |
| `test_consolidation_merges_same_entity_events` | 事件合并后处理 | 两个共享主体的事件自动合并：主张迁移、命题并集、merge 版本与 merge_event 通知 |
| `test_consolidation_keeps_unrelated_events` | 合并的负例 | 不同公司、不同话题的两个事件保持独立 |
| `test_consolidation_merges_then_is_idempotent` | 合并幂等 | 再次运行无新增合并 |
| `test_different_entities_never_merge` | 主体隔离（回归） | 成飞/左江/法尔胜三个独立事件不得互相合并（曾因 JSON 字符集 bug 全并） |
| `test_four_timestamps_recorded` | 四个时间戳 | 每篇文档都有 disclose_time / crawl_time / event_time；事件有 event_time 与 updated_at |
| `test_expiry_marks_event_once` | 过期处理 | 超过 60 天无更新：结论追加过期提示（不覆盖证据判定）、过期通知只发一次 |
| `test_offline_cache_replay_is_deterministic` | 回放确定性 | 同一原始文档两次引导得到相同事件数与状态 |

## 二、数据缺失 / 接口异常（tests/test_api_failure.py）

| 用例 | 覆盖点 | 断言要点 |
|---|---|---|
| `test_llm_down_falls_back_to_rules_and_marks_degraded` | LLM 接口失败 | 主链路仍产出主张；文档标记 `fetch_status=degraded`，绝不静默产出"正常"结论 |
| `test_rule_extraction_still_drives_verdicts` | 降级模式下判定仍正确 | 官方澄清公告在规则抽取下仍正确判定为 denied |
| `test_empty_body_rejected_by_api` | 空数据 | POST 空正文返回 400，明确报错 |
| `test_missing_timestamps_do_not_crash` | 时间缺失 | 披露时间缺失时链路可用，抓取时间始终存在，缺失如实展示 |
| `test_unknown_source_gets_default_weight` | 未知来源 | 证据权重落在合法区间 [0,100]，不崩溃 |
| `test_duplicate_replay_is_idempotent` | 重复入库 | 同一文档重复入库合并且事件数不变 |

## 三、合规边界（tests/test_compliance.py）

| 用例 | 覆盖点 | 断言要点 |
|---|---|---|
| `test_conclusion_never_contains_advice` | 无投资建议 | 结论不含"建议买入/目标价"等表述；包含"不构成任何投资建议" |
| `test_sanitize_strips_advice_phrases` | 清洗器 | 建议性短语被替换为中性标记 |
| `test_claim_types_strictly_separated_and_traceable` | 四分类与可追溯 | 传闻与事实严格分开；每条主张绑定来源文档、披露时间与逐字 quote |
| `test_api_disclaimer_present` | 接口免责声明 | /api/events 与 /api/stats 均返回免责声明 |

## 四、真实数据端到端验证（部署前手工执行）

3. **公网验证**：https://event-radar-fcy0.onrender.com 首页 200、4 事件数据正确、在线提交文档链路可用。
4. **演示文档效果**（在库副本上验证后合入）：左江"更正公告"演示文档触发命题模糊归并、事件状态【已完结】→【已更正】翻转、1 条 state_change 通知。

## 五、如何复跑

```bash
pip install -r requirements.txt
cp .env.example .env        # 填入 DEEPSEEK_API_KEY（演示数据已内置缓存，无 key 也可离线回放）
python -m pytest tests/ -v  # 全部 22 个用例
python -m scripts.bootstrap_demo --offline   # 从缓存重建演示库
uvicorn app.main:app --port 8000
```
